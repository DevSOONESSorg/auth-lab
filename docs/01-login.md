# 第1段：ログインを動かして、仕組みを確かめる（開発者）

目安：60〜90分

## ゴール

- 「Cookie に入っているのはセッションIDだけ」「パスワードはハッシュで保存」を、自分の目で確かめて説明できる
- `requireLogin` / `requireRole` が何をしているか読める

## 手順

### 1. ログインしてみる

1. `docker compose up --build` で起動し、<http://localhost:4000> を開く
2. `admin` / `password` でログインする
3. ホーム画面に出ている「セッションID」と「Cookie」の説明を読む

### 2. Cookie を見る

1. ブラウザの開発者ツール（F12 または 右クリック → 検証）を開く
2. Application タブ（Firefox は Storage）→ Cookies → `http://localhost:4000`
3. `sid` という Cookie を探す。値をよく見る

**確認**：値の中に `admin` や `情シス` という文字は入っていますか？ → 入っていません。Cookie には「セッションID」と「その署名」だけがあり、名前や役割はサーバー側にあります。

### 3. Cookie を消す

1. `sid` を右クリック → 削除
2. ページを再読み込みする

**確認**：ログイン画面に戻されます。サーバー側のセッションは残っていますが、ブラウザが「自分がどのセッションか」を忘れたので、もう結びつけられません。

### 4. 別のブラウザでログインする

シークレットウィンドウ（または別のブラウザ）で同じ `admin` でログインし、ホーム画面のセッションIDを比べる。

**確認**：別のIDになります。「ログイン状態」はユーザーではなくブラウザごとに存在します。

### 5. パスワードを間違え続ける

ログアウトして、`higa` で間違ったパスワードを6回入れる。

**確認**：5回目でロックされ、正しいパスワードでも入れなくなります。`admin` でログインして「監査ログ」を見ると、失敗が記録されています。ロックは `admin` の「PWリセット」で解除できます（または10分待つ）。

### 6. 有効期限を短くする

`web/src/config.js` の `SESSION_MAX_AGE_MS` を `60 * 1000`（1分）に変えて保存する（自動で再起動されます）。ログインして1分以上放置してから何か操作する。

**確認**：ログイン画面に戻されます。戻したら `30 * 60 * 1000` に直しておく。

### 7. サーバーを再起動する

別のターミナルで `docker compose restart web` を実行し、ブラウザを再読み込みする。

**確認**：ログアウトになります。セッションがサーバーのメモリにあるためです。README の「ログインの仕組み」を読んで、本番ではどうするかを確認する。

### 8. コードを読む

次の順で読むと流れが追えます。

1. `web/src/auth/routes.js` の `router.post('/login')` — 照合 → 失敗回数 → `req.session.user` に入れる
2. `web/src/auth/users.js` の `hashPassword` / `checkPassword` — bcrypt
3. `web/src/auth/middleware.js` — `requireLogin` と `requireRole`
4. `web/src/server.js` の `session({...})` — Cookie の設定（httpOnly / sameSite / maxAge）

## 確認チェックリスト

- [ ] Cookie `sid` の中にユーザー名が入っていないことを確認した
- [ ] Cookie を消すとログアウトになった
- [ ] 別ブラウザではセッションIDが違った
- [ ] 5回間違えてロックされ、監査ログに残った
- [ ] 有効期限を1分にして切れるのを確認した
- [ ] サーバー再起動でログアウトになる理由を説明できる
- [ ] `requireRole('admin')` を外すと一般社員でもユーザー管理が見られることを試した（試したら戻す）

## 発展（余裕があれば）

- `web/src/db.js` の users テーブルを SQLite Viewer で開き、`password_hash` が `$2a$10$...` で始まる意味不明な文字列であることを確認する
- 同じパスワード `password` の `admin` と `higa` で、ハッシュが違う理由を調べる（ヒント：ソルト）
- `secure: false` を `true` にすると http://localhost でログインできなくなる理由を調べる
